📊 Database Schema (Core Tables)
1. Users
user_id (PK, UUID or auto-increment)

username (unique)

password_hash (never store plain text)

email (optional, for recovery/2FA)

telegram_id (optional, for Telegram verification)

register_date

expire_date (nullable, for subscription/expiry)

status (active, expired, banned, pending)

baseline_pin (optional, for secondary auth)

2. Auth Logs
log_id (PK)

user_id (FK → Users)

action (login, logout, password_change, 2FA_setup, etc.)

timestamp

ip_address (optional, for security)

device_info (optional)

3. Audit Trail
audit_id (PK)

actor_id (FK → Users, who made the change)

target_id (FK → Users, whose record was changed)

action (create, update, delete)

relative_path (e.g., /api/users/update)

timestamp

4. Sessions / Tokens
session_id (PK)

user_id (FK → Users)

token (JWT or random string)

issued_at

expires_at

revoked (boolean)

🛠️ Backend Structure (API CRUD)
Core Endpoints
User Management

POST /users → create user

GET /users → list/filter users (active, expired, by year/month)

GET /users/{id} → fetch single user

PUT /users/{id} → update user (username, password, email, 2FA, etc.)

DELETE /users/{id} → remove user

Authentication

POST /auth/login

POST /auth/logout

POST /auth/refresh (token refresh)

POST /auth/2fa/setup

POST /auth/2fa/verify

Logs & Audit

GET /logs → fetch login/logout logs

GET /audit → fetch audit trail

POST /audit → record changes automatically via middleware
